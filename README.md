# 無限ヒーリングピアノ

静かなピアノ曲を、途切れることなく生成し続けるブラウザアプリ。
音源ファイルも学習済みモデルも使わず、すべてブラウザの中で音を作る。

同じ6文字のシードからは、曲も演奏の揺らぎも楽譜も完全に同じものが出る。

```
npm start        # http://localhost:8080/
```

初回のクリックまで音は鳴らない（ブラウザの自動再生制限）。

## 動かす

| 入口 | 用途 |
|---|---|
| `index.html` | 開発用。`src/*.js` をモジュールとして読む。サーバ経由で開く |
| `melody-generator.html` | 配布用。1ファイルで完結し、ダブルクリックで開く（1.3 MB） |
| `algorithm.html` | 生成アルゴリズムの解説。試聴つき |

`melody-generator.html` は **生成物**。手で編集せず、`src/` を直してから
`npm run bundle` で作り直すこと。

```
npm start          # 開発サーバ（キャッシュ無効）
npm test           # テスト 485 件
npm run bundle     # 単一ファイル版を再生成
npm run data       # 断片カタログと和音進行を作り直す（数分かかる）
```

開発サーバをわざわざ自前で持っているのは、キャッシュを完全に切るため。
`python3 -m http.server` は `Cache-Control` を返さず、ブラウザが
「更新からの経過時間の1割」を勝手に鮮度とみなすので、
**直した直後のファイルほど再確認されずにキャッシュから返る**。

## 仕組み

旋律の美しさは音符ごとの逐次的な決定からは生まれない。この生成系は
二層に分かれていて、上の層は曲を作る前に一度だけ走る。

**断片層（事前）** — 公有の名旋律125曲・1768音の統計から旋律型490種を抽出し、
それを繋いで作った候補300,000個を評価関数で採点、層化抽出で999個を選ぶ。
各断片は「どの和音に乗るか」を事前計算して持つ。

**構造層（実時間）** — 楽節構造（A–A′–B–A″）と起伏曲線に従って断片を選び、
並べる。個々の音符には触れない。1曲の組み立ては実測 6.5 ミリ秒。

詳しくは **[生成アルゴリズムの解説](algorithm.html)** に、数式と実測値と
試聴つきで書いてある（コーパスの収録曲一覧もそこにある）。

## 触るときに壊しやすいところ

どれも一度壊した場所で、コード中にも同じ注意が書いてある。

**乱数** — `Math.random()` を使ってよいのは `synth.js`（リバーブとデチューン）と
`player.js` のシード生成だけ。作曲と演奏は必ずシード由来の PRNG を使う。
`composeSong` の中の**乱数の消費順を変えない**こと。順序が変わると、
同じ曲コードから別の曲が出る。

**和音語彙の順序** — 断片の和音適合は `CHORD_VOCAB` の**添字**で保存されている。
途中に挿入すると全断片の適合情報が別の和音を指す。追加は必ず末尾へ。

**曲コード** — 選択肢の添字を並び順に1文字ずつ書く形式（`#k3f9zq.114`）。
`code` を持つパラメータを途中に挿入すると、共有済みの URL がずれる。

**声部の配置** — 和音を動かしてよいのはオクターブ単位の移動と上声の省略だけ。
半音単位で押し込むと別の和音になる。`nearestOctave` は範囲が12半音を切ると
端へ丸めて音名を変えるので、天井の計算には使えない（`placeUnder` を使う）。

**iOS の音声セッション** — 無音の `<audio>` を `muted` にしてはいけない。
消音した要素は再生とみなされずセッションを取れず、本体側面の消音スイッチで
音が丸ごと止まる。再生開始はクリックハンドラの中から呼ぶこと。

**単一ファイル版** — `melody-generator.html` は生成物。手で編集しない。

## データを作り直す

```
npm run data
```

`tools/data/patterns.json`（コーパスから抽出した型）と
`src/data/*.json`（断片カタログと和音進行）を作り直す。固定シードなので
何度実行しても同じ JSON が出る。断片の生成は候補30万件を評価するため数分かかる。

コーパス自体を増やすときは `tools/corpus.js` に曲を足し、
`node tools/extractPatterns.js` で型を抽出し直してから `npm run data`。

## 出典

旋律型の抽出元は公有の名旋律125曲（作曲者56人・99曲と伝承曲26曲）。
公有の判定は「作曲者の没年が1955年以前、または伝承曲」で、
収録曲の最も新しい没年は1952年。採譜したのは各曲の主旋律の一節だけで、
和声も伴奏も採っていない。全曲の一覧は
[解説ページの付録](algorithm.html#appendix) にある。

# 70〜80年代ポップバラード編曲層 設計書

作成日: 2026-08-20

## 1. なぜ作るか

初版の設計書は方向性をこう書いている。

> 品質目標は「涙を流すほど美しいメロディ」。**リズムの面白さではなく**、
> メロディーの輪郭と和声の陰りで感情を動かすことを優先する。

この判断を意図的に反転する。実装は完成度高くこの方針を守り切っていて、
結果として **リズムに関しては一切の変化を持たない曲** が出るようになった。
100曲を実測した数字が、それをそのまま示している。

| 症状 | 実測（100曲・既定設定） | 原因 |
|---|---|---|
| 伴奏が全曲・全小節で完全に同一 | 例外は最終小節の1つだけ | `ACCOMP_OFFSETS` が固定 |
| 1曲の小節リズム型 | **6.9種類 / 31小節** | 断片プールのリズム型が40種しかない |
| スロットが前の断片と同リズム | **47%**（`transpose` 394 + `rhythm` 386 / 1600） | 楽節構造の設計上そうなる |
| 小節線をまたぐ音 | **0.6%**（85 / 14609） | 断片が2小節で閉じ、`fitsBar` が小節単位 |
| 2拍以上伸ばす音 | **5.0%** | 断片の音価の中央値が0.5拍 |
| 和声リズム | 常に1小節1コード | 4小節進行を機械的に展開 |

要するに **「食い」「タイ」「休符の間」「伴奏の変化」が原理的に一音も出ない**。
現代のポップバラードが人を動かすのは、旋律の音程よりむしろこの4つの時間的な仕掛けによる。

## 2. 到達点

**70〜80年代の日本の歌謡曲／ニューミュージック系バラード**、およびその手本だった
アメリカ・イタリアのポップバラードの響き。8ビート系（3連＝12/8のスローロックは扱わない）。

既に実装済みの「最終セクションの半音上げ転調」は、まさにこの時代の定石であり追い風になる。

## 3. 範囲

本書は **案1（編曲層）** のみを扱う。全体は2段階。

| | 内容 | 本書 |
|---|---|---|
| 案1 | 編曲層の新設。伴奏型・ベース型・食い・タイ | ○ |
| 案2 | 断片データの刷新。旋律の音程の語彙を現代化 | 別文書 |

案1 → 案2 の順にする理由は2つ。案1だけで「リズムが単調」の大半が消えて耳で確認できること。
そして **食いという語彙は伴奏が動いていて初めて意味を持つ** こと。順序が逆だと案2の投資が体感できない。

### やらないこと

- 打楽器の追加（声部は melody / accomp / bass / pad の4つのまま）
- パッドの作り直し（持続音のまま）
- 3連・12/8（`export.js` の `DIVISIONS = 4` と `notation.js` の符頭表に手が入るため。案2で再検討）
- 16分刻みの伴奏（90年代以降の語彙）
- 同音連打からの跳躍（音程の語彙なので案2）
- 音域カーブ（`curveFor`）とテンポの変更（断片選択が変わりシード互換が壊れるため案2へ）
- 新しい設定パラメータ（曲コードの形式は変えない）

## 4. モジュール境界

### 4.1 新モジュール `src/arrange.js`

責務を **「どの音を鳴らすか＝`compose.js`」「いつ鳴らすか＝`arrange.js`」** で分ける。

`compose.js` に残すもの（音高の決定）:
`chordVoicing` / `placeUnder` / `withoutRub` / `melodyCeiling` / `nearestOctave`

`arrange.js` へ移すもの（時間の決定）:
`ACCOMP_OFFSETS` / `ACCOMP_DUR` / `arpeggioIndex` / ベースの全音符

### 4.2 `composeSong` を5段に組み直す

現行は「セクションごとに スロットループ → 小節ループ」。これを曲全体で段に分ける。

| 段 | 内容 | 乱数 |
|---|---|---|
| 1 | 和音の割り当てとスロット→旋律（現行のセクションループそのまま） | `seed` |
| 2 | 息継ぎ・クライマックス・脱力・最終音（現行） | `seed` |
| 3 | 食い／タイ（`arrange.js`） | `seed:arr` |
| 4 | 声部配置 → `barInfo`（現行の小節ループから伴奏生成を抜いたもの） | なし |
| 5 | 編曲（`arrange.js`） → `accomp` / `bass` / `pad` | `seed:arr` |

現行の小節ループは乱数を1つも消費しないので、**段1の乱数消費順は完全に不変**。

副次的に既存の不整合が1つ直る。今は息継ぎを全セクション組んだ**あと**に適用するのに、
天井（`melodyCeiling`）は息継ぎ**前**の旋律で計算されていて、息継ぎの小節だけ
伴奏が不必要に低く抑えられている。段4を段2の後ろに置くことで解消する。

### 4.3 乱数の分離 — シード互換の設計

`perform.js` が `seed + ':perf'` を使うのと同じやり方で、編曲は
**`seed + ':arr'` の独立した乱数列**を使う。これにより:

- **同じ曲コードから、旋律の音程と和声はこれまでと1音も変わらず出る**。変わるのはリズムと伴奏だけ
- 共有済みURLは「同じ曲の新しい編曲」として鳴る
- 開発中に伴奏型を足し引きしても旋律が動かないので、聴き比べができる

この保証を守るため、案1では音域カーブとテンポには手を入れない（3節「やらないこと」）。

### 4.4 `song` オブジェクトへの追加

```js
arrangement: {
  accompPatterns: [{ startBar, pattern }],  // セクションごとの伴奏型の名前
  bassPatterns:   [{ startBar, pattern }],
  anticipated:    [beat, ...],              // 食わせた音の（変更後の）拍
}
```

解説ページ（`algorithm.html`）と楽譜側が編曲を説明できるようにするための記録。

## 5. 伴奏とベースの型

### 5.1 型の表し方

`placeUnder` が返した `voicing`（昇順の実音、長さは2〜4で変動）に対して、
**添字ではなく役割で**指定する。データの長さが変わっても型が壊れないため。

```js
// 1小節ぶんの伴奏型
[{ beat: 0, voice: 'low',   dur: 1 },   // low   = 最低音
 { beat: 1, voice: 'upper', dur: 1 },   // upper = 最低音より上を和音で
 { beat: 2, voice: 'low',   dur: 1 },   // arp   = 三角波で巡回（現行の arpeggioIndex）
 { beat: 3, voice: 'upper', dur: 1 }]   // all   = 全構成音
```

### 5.2 伴奏型の語彙

| 型 | 中身 | 役どころ |
|---|---|---|
| `sustain` | 拍0に全構成音、4拍保持 | いちばん薄い。Aメロの入り |
| `broken` | 低音→上部→低音→上部（4分） | 歌謡曲バラードのピアノの正体。既定 |
| `brokenHalf` | 低音を2拍伸ばし、間に上部を落とす | `broken` の静かな版 |
| `arp8` | 8分の三角波（現行の `ACCOMP_OFFSETS`） | 流れが要るところ |
| `pulse8` | 和音を8分で押す | サビ。いちばん厚い |
| `syncope` | 0 / 0.5 / 1.5 / 2.5 / 3 / 3.5 に食って置く | 8ビートの推進力 |

### 5.3 ベース型の語彙

| 型 | 中身 |
|---|---|
| `whole` | 全音符（現行） |
| `rootFifth` | 拍0に根音、拍2に5度 |
| `rootOctave` | 拍0に根音、拍2にオクターブ上 |
| `drive` | 4分で根音を刻む |
| `anticipate` | 拍0に根音＋拍3.5で**次の小節の根音を先取り**（＝食い） |

`anticipate` は次の小節の `bassNote` を要するが、編曲は曲全体の `barInfo` を一度に見るので取れる。
8ビートバラードの推進力の正体はここにある。**曲の最終小節では先取りしない**（次の小節が無い）。
転調のつなぎ目では先取りする — 新しい調の属和音の根音を先に鳴らすのは、むしろ自然な導き方になる。

### 5.4 セクションへの割り当て

70〜80年代の定石どおり、**Aメロは薄く、サビで一気に厚く、最後は収める**。

| セクション | 伴奏 | ベース |
|---|---|---|
| A（提示） | `sustain` / `brokenHalf` | `whole` |
| A′（高まり） | `broken` / `arp8` | `rootFifth` |
| B（サビ） | `pulse8` / `syncope` / `arp8` | `rootOctave` / `anticipate` |
| A″（着地） | `broken` → `brokenHalf` | `whole` |

さらに **セクションの折り返し（スロットの前半／後半の境目）で型が1段上がる**。
表の2つの型は「前半／後半」の順で、後半のほうが必ず密度が高い。A″ だけは逆に下げる。
最終小節は現行どおり刻みを止めて和音を置く（`FINAL_ACCOMP_VEL`）。

これで1曲の伴奏の「顔」が最低6つになる。現行は32小節すべてで1つ。

### 5.5 ベロシティ

現行の `ACCOMP_VEL = 0.3` は「8分が8個」を前提にした値。型ごとに音数が変わるので、
**型に係数を持たせる**（`sustain` は同時に鳴る音が多いので下げ、`broken` は音が少ないので上げる）。
係数の値は実装時に実測で決め、根拠をコード中のコメントに残す。

## 6. 食いとタイ

段3で、旋律の**音程には一切触れず拍と音価だけ**を書き換える。

### 6.1 食い（アンティシペーション）

小節の拍0にある音を、前の小節の**拍3.5へ半拍前倒し**し、音価を0.5拍伸ばす（終わりは動かさない）。
結果として小節線をまたぐので、楽譜では自動的にタイになる。

食ってよい条件:

1. 直前の半拍が空いていること（前の小節の3.5拍に音が無い）
2. **曲の1音目は食わない** — 拍の位置を最初に示す役目がある（`preferDownbeat` の意図）
3. **クライマックスの音は食わない** — `climaxBeat` がずれ、`perform.js` のテヌートと二重に掛かる
4. **息継ぎの小節（`breathBar`）の直後は食わない** — 息を吸った直後に食い込むと息継ぎが消える
5. セクションごとの確率で抽選する。初期値は **A: 15% / A′: 35% / B（サビ）: 70% / A″: 30%**。
   曲を通して単調にならず、かつサビで推進力が立つ配分。実装後に実測で調整し、根拠をコメントに残す

前の小節の和音との衝突は明示的には検査しない。段3を段4（声部配置）より前に置くので、
`withoutRub` が食った音を見てパッド側を削る。ただし `withoutRub` の「表に出ている音」の判定
（`n.beat % 2 === 0 || n.dur >= 1.5`）から食った音が漏れるので、
**食った音は無条件に表扱いにする**。

次の和音の和声音が前の和音の上で鳴ること自体は潰さない。それが食いの響きそのものだから。
潰すのはパッドが唸る場合だけ。

### 6.2 タイ（フレーズ末の伸ばし）

ここで言うフレーズ末とは `phraseEndFlags` が真を返すスロットのこと（楽節計画の区切り）。
そのスロットの最後の音を、**次の音の手前0.5拍まで**伸ばす（最大4拍）。

- 0.5拍の隙間を必ず残すので、「伸ばし切って息を吸う」形になり、間は潰れない
- 小節線をまたげばタイになる
- **息継ぎの小節へは伸ばさない**（伸ばすと息継ぎが消える）

### 6.3 副次的に直すもの

`melodyCeiling` は音の**開始拍**しか見ていないので、小節をまたいで鳴っている音が
次の小節の天井に効かない。食いとタイでまたぐ音が増えるので、**鳴っている区間で見る**ように直す。

### 6.4 `perform.js` への影響

- `phrasePeaks` / `phraseLastIndexes` は8拍でフレーズを切るので、拍8.0の音が7.5へ移ると
  前のフレーズに属することになる。**放置する** — 食いはフレーズの先取りで、
  実際の演奏でも前の流れの中から出てくるものだから
- `climaxBeat` は食わないので不変。リタルダンドと「ためらい」も拍で見るのでそのまま

## 7. 互換性

| 対象 | 影響 |
|---|---|
| 曲コード | **形式・意味とも不変**。新パラメータを足さない |
| 同じシードの旋律 | **音程は完全に不変**。拍と音価だけが変わる |
| 同じシードの和声 | 進行・転調とも不変。声部配置は息継ぎの小節でのみ変わりうる（4.2 の不整合修正） |
| `CHORD_VOCAB` の順序 | 触らない |
| 楽譜（`notation.js`） | 無改修。`splitAcrossBars` が既にタイを処理する。実データで描画を確認する |
| 書き出し（`export.js`） | 無改修。`tie` / `tied` の経路が既にある。MusicXML と MIDI の両方を実データで確認する |
| `melody-generator.html` | 生成物。`npm run bundle` で作り直す |
| `algorithm.html` (+ en / zh) | 生成アルゴリズムの説明が変わるので更新が要る |
| `src/data/*.json` | **触らない**（案2で作り直す） |

## 8. 検証

### 8.1 数値目標

実装後、100曲の実測で次を満たすこと。1節の表と同じ計測方法で比較する。

| 指標 | 現状 | 目標 |
|---|---|---|
| 1曲の伴奏型の種類 | 1 | **6以上** |
| 小節線をまたぐ音 | 0.6% | **8%以上** |
| 2拍以上伸ばす音 | 5.0% | **12%以上** |
| 1曲の小節リズム型 | 6.9 | **10以上**（※） |
| 旋律の midi の並び | — | **案1の前後で完全一致** |

※ この指標だけは案1の射程を超える可能性がある。断片プールのリズム型が40種しかないという
根本原因は案2で扱うもので、案1の食いとタイは既存の型を変形するにとどまるため。
未達なら「案2でどれだけ増やす必要があるか」の数字として引き継ぐ。

最後の1行が 4.3 のシード互換の保証そのものであり、回帰テストとして最も重い。
実装前に固定シード群の旋律をスナップショットとして取り、実装後に突き合わせる。

### 8.2 テスト

既存485件のうち、伴奏の形を直接主張しているのは3つ。

- `test/compose.test.js:897` / `:1629` / `:2330` … `song.accomp.length === (song.bars - 1) * 8 + 1`

これらは「8分が8個」という**古い不変条件**なので、新しい不変条件へ書き換える。

- 伴奏が途切れない（どの小節にも音がある）
- 伴奏型がセクションごとに変わる
- 最終小節は刻みを止めて和音を置く

新規に `test/arrange.test.js` を置き、次を検査する。

- 型の展開が `voicing` の長さ2〜4のいずれでも壊れない
- `anticipate` が次の小節の根音を鳴らし、曲の最終小節を越えて先取りしない
- 食いの5条件（曲頭・クライマックス・息継ぎ直後・空きなし・確率）が守られる
- タイが次の音の手前0.5拍を必ず残す
- `seed:arr` が同じなら編曲が完全に再現する

### 8.3 耳での確認

数字が目標を満たしても、それは「単調でなくなった」ことの証明でしかない。
`npm start` で実際に通しで聴き、70〜80年代バラードとして成立しているかを人が判断する。

## 9. 案2への申し送り

案1で意図的に残した課題。

- 旋律の音程の語彙が1955年以前の名旋律125曲由来のまま（順次進行69.1%、同音連打が乏しい）
- 断片のリズム型が40種しかなく、楽節構造がその47%をさらに複製する
- 断片が2小節で閉じるため、断片の側から食いを持つことができない（案1は事後変換で作っている）
- 和声リズムが常に1小節1コード
- サビの発声位置（音域カーブ）が低い
- 3連・12/8 の可否（`export.js` の解像度を上げるかどうか）
